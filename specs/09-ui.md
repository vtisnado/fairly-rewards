# UI: Screens (draft)

All screens are mobile-first, English, and show a visible "Testnet demo: test money" badge.

## Merchant (`/business/<slug>`)
- **UI-001** Setup at `/business/new` in five steps (Brand, Rewards, Boosts, Locations, Fund): name, web address (slug, checked for availability), type of business (MCC), brand color presets or custom, optional logo link, cashback %, tiers with perks, royalty %, expiry, daily cap per location, boosts, locations picked on a map, and test money for the pool. Live preview of the pass card. After launch, the owner edits name, color, logo, cashback and perks from the same form; the other terms stay fixed.
- **UI-002** Dashboard per program: member sales over 7, 30 or 90 days, cashback given, royalties earned, pool balance with runway and a fund button (faucet shortcut in the demo), passes issued, cashback today vs. cap, returning-customer share, live recent events. Cashback and royalty show an info button that explains each term. Periods can be a custom date range from a calendar and compared with the previous period. The sidebar collapses to icons with tooltips. Tables are paginated. A customer row and a device row open a side panel with details and paginated history. The demo program can add locations.
- **UI-003** Counter devices and managers connect with a pairing code: the device (`/cashier/<slug>`) or manager (`/business/<slug>/team`) creates its own key, registers its public account id and shows a 6-character code valid for 15 minutes; the owner (or a manager, for devices at their location) types the code to add it on chain. Private keys never leave the device and never travel in links. Devices can be paused and reactivated.
- **UI-004** Print/display the join QR code for `/join/<slug>`.

## Cashier (`/cashier/<slug>`)
- **UI-010** Identify the customer by scanning a QR with the camera (native `BarcodeDetector` when available), by typing the card code (`W8W-CYA`), or, on the demo program, by picking one of the cards issued in the last hour. A customer account QR without a card issues the card first (PASS-002).
- **UI-011** Numeric keypad for the amount (cents, max 1,000.00), live cashback preview with the effective rate, optional category chips (Coffee, Food, Bakery, Retail, Other), confirm, then a success screen with cashback added and tier-up when it happens.
- **UI-012** "Balance code" mode: type the code shown on the customer's phone (`W8WCYA-3`). The screen MUST show amount or perk and MUST mark the code as honored so it cannot be honored twice. A live list shows codes waiting at the counter.
- **UI-013** Layout follows the prototype: two columns on tablets (card left, keypad right), stacked on phones. The header shows the location and cashback issued today against the daily cap, updated in real time.
- **UI-014** A paired device signs `issue_pass` and `record_purchase` with its own key through the relay, and proves its key to the server when it honors a balance code. The shared demo program also works without pairing, signed on the server with the demo cashier key.

## Customer (`/join/<slug>`, `/pass/<token_id>`)
- **UI-020** Join screen: one button "Get my card" → onboarding (ONB) → QR to show the cashier.
- **UI-021** Pass screen: card artwork, balance in USD, tier, progress to next tier, perks, expiry warning, pass QR.
- **UI-022** Actions: redeem (amount), claim perk, list for sale, cancel listing, export key.
- **UI-023** Link to the pass in a NEAR explorer.

## Market (`/market`)
- **UI-030** List of passes for sale: artwork, program, tier, value inside, price, buy button.

## Art (`/api/art/<slug>/<tier>.svg`)
- **UI-040** Returns an SVG card using program colors and tier styling (Bronze/Silver/Gold visual differences). Cacheable.

## Landing (`/`)
- **UI-050** One-screen explanation for judges: problem, 3-step flow, "Try the demo" buttons for merchant, cashier and customer roles.
